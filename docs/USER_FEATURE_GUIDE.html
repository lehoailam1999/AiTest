Từng bước

  1. Sidebar trái → nhóm Design → Projects.

    Tiêu đề trang: Dự án. Góc phải: Unit test · E2E test · Tạo mới.

  2. Bấm Tạo mới (hoặc Sửa trên một dòng).

    Tag xanh Connected. Cột bảng: «Đã gắn source root» + «IDE: Connected».

    Sidebar «Dự án hiện tại» đổi tên. Sẵn sàng sang chức năng 02.

  • Workspace kích hoạt; hệ thống quét stack (xUnit / vitest / pytest…).
  • Connect IDE xong mới Gen Unit / E2E được (fail-closed, không fallback LLM Backend).

Requirement

Quản lý theo Requirement (mỗi phần nghiệp vụ một mục). Trong Requirement: tài liệu → phân tích → sinh TC Unit/E2E → duyệt. Sau Approved: Unit test · E2E test.

Mỗi Requirement = tài liệu + phân tích → TC. Muốn viết TC cho phần khác — tạo Requirement mới.

Từng bước

  1. Sidebar → Requirement.

    Nếu chưa gắn source: banner vàng «Chưa gắn source root» + link về Projects.

  2. Bấm Requirement mới (hoặc Mở một dòng). Toolbar hub: Tải lại · Requirement mới.

    Vào Studio. Header: Tất cả Requirement · Thêm tài liệu. Thanh 4 bước: Tài liệu · Phân tích · Tạo test case · Duyệt test case.

  3. Ô Tài liệu → Thêm tài liệu: upload .md / .docx hoặc dán mô tả.

    Số file hiện trên hint journey (vd. «2 file»).

  4. Ô Phân tích → bấm Phân tích (hoặc Phân tích lại).

    Knowledge: Business Rules, Validation, Edge, Error, actor, use case. Status «Sẵn sàng» hoặc «Cần phân tích lại».

  5. Ô Tạo test case → chọn engine Unit hoặc E2E → Chốt snapshot và tạo test case (E2E: «…tạo TC E2E»).

    Job sinh TC chạy Backend. Draft xuất hiện để duyệt ở bước 03. Jobs sinh TC không ghi path mã nguồn.

Kết quả

  • Bảng quy tắc trên UI + danh sách TC nháp (Draft).
  • Knowledge lưu dưới .ai-test/ trên repo khách.

Quick-start

Năm bước cho Tester mới

Làm đúng thứ tự này — đừng Gen khi chưa Approve và chưa Connect IDE.

  1. Sign in → Projects → Tạo mới → Chọn thư mục → Connect IDE → Chọn dự án.

    Sidebar hiện tên dự án «Đang làm việc».
